# Local model folders in Settings

VoiceStudio supports an explicit local checkpoint folder for the existing **OmniVoice** and **MLX-Audio** TTS engines. The control is shown on each supported engine row under Settings → Models → TTS and uses the native folder picker.

The folder must contain `config.json` and at least one supported weight file (`.safetensors` or `.bin`), plus the engine-specific tokenizer and sub-checkpoint assets. OmniVoice metadata must identify an OmniVoice/VoiceStudio checkpoint. Qwen Base metadata is rejected for MLX VoiceDesign; a VoiceDesign checkpoint must identify itself as such. Settings reports the saved path, model name/type, file-validation result, and the runtime cache state. File validation is inspection only; `valid` does not claim that synthesis has run or that a real checkpoint can load. The `loaded`/`not_loaded` indicator reports cached runtime state only; it does not load or probe the checkpoint.

The **Discover** control opens the native directory chooser for a user-selected parent. It sends a one-shot native capability, never a raw renderer filesystem path. The backend checks only immediate child directories (up to 100, excluding symlinks), lists each candidate's full path and actionable compatibility diagnostics, and does not select, persist, load, download, copy, convert, or repair any candidate. A candidate must still be explicitly chosen before use. Discovery-issued selections are bound to the canonical directory's device/inode identity and rejected if that directory is replaced before redemption or persistence. Checkpoint metadata, weights and tokenizer assets must be actual files/directories, not symlinks; copy the actual assets into a standalone checkpoint folder if needed. These checks do not make checkpoint contents immutable or provide fd-atomic loading against a concurrent same-user writer.

The selected path is stored per engine in the backend preferences and is applied immediately after the current engine is unloaded. It is also honored after restart. **Use default** explicitly clears the saved override; it does not delete, move, or modify model files. A missing or incompatible folder is an error; local-path failures never trigger an automatic download or repair.

This feature does not change the global Hugging Face model-cache directory in Settings → Storage, does not copy model files, and does not alter user audio. Other engines remain on their existing model-management paths until their loaders expose an equivalent local-checkpoint contract.
