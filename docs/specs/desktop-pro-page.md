# Desktop Pro checkout release contract

VoiceStudio Free retains unlimited local voice creation, transcription, dubbing, Stories, Audiobooks, batch jobs, local exports, reusable recipes, watch folders, remote-device compute, remote workers and GPU sharing. Existing AGPL features are excluded from paid entitlement gates. The remaining proposed Pro scope is application licensing, additional batch rules/reports, revision history, delivery packages and project preflight; each requires review against existing free functionality before implementation. Application licensing does not grant model or generated-output rights.

The current page presents $99 per user yearly or $299 per user lifetime. Yearly renews; lifetime is one payment with no renewal and includes lifetime updates. These offers remain subject to the release gates below. Enterprise is a contact plan for customised deployment, policy controls, SSO/SAML, opt-in analytics and dedicated support. Pro does not change GNU AGPL-3.0 software distribution rights; a separate commercial agreement handles closed-source distribution. Payment/licensing provider, default Pro engine and private-repository versus plugin structure remain undecided.

The Electron Pro page shows Pro, Lifetime, and Enterprise cards in one row. Pro and Lifetime let buyers select 1–99 users, show the calculated total, and link to `https://voicestudio.sh/pro` with the plan and quantity. Enterprise links to the commercial contact page. The existing client integration targets Lemon Squeezy; choosing it for production remains a separate decision. If selected, the website may show its hosted checkout only when all release gates are true and both live offers are verified. Lemon Squeezy handles payment, receipts, and emailing licence keys. The app activates, validates, and deactivates a key through its public License API. It accepts only the configured store, product, and one of the two purchasable plan variant IDs. Main never returns the key to the renderer after submission. The app checks status when the Pro page opens; activation/deactivation are explicit actions. The activation form opens in a modal from the pricing section. Free workflows do not require a network call.

## Release gates

- Finalize additional paid capabilities, then implement their entitlement checks in Electron main/backend. Never add Pro gates to the existing free recipes, watch folders, remote-device compute, remote workers or GPU sharing. Verify new paid capabilities on macOS, Windows and Linux. Until this is done, `VOICESTUDIO_PRO_FEATURES_RELEASED` stays unset.
- Fulfil purchased user quantity as the licence activation entitlement. Lemon Squeezy checkout quantity changes the charge but does not by itself change a variant's fixed activation limit, so a verified webhook or equivalent fulfilment step must set and audit the purchased activation count before multi-user checkout is enabled.
- Create live yearly and lifetime Lemon Squeezy variants with licence keys enabled. Verify the yearly subscription interval and the lifetime non-expiring key. Record store, product, and both variant IDs. Confirm each displayed price against checkout, tax presentation, activation limit, renewal and cancellation terms, and refund policy in a live checkout. Test variants must never be used for a production build.
- Review and approve desktop Pro purchase terms and privacy wording with qualified counsel. Until approved, `VOICESTUDIO_PRO_TERMS_APPROVED` stays unset.
- Build Electron with `VOICESTUDIO_PRO_STORE_ID`, `VOICESTUDIO_PRO_PRODUCT_ID`, `VOICESTUDIO_PRO_YEARLY_VARIANT_ID`, and `VOICESTUDIO_PRO_LIFETIME_VARIANT_ID`. Each must match the website's live offer. An unconfigured build cannot activate keys.
- Test purchase, email delivery, activation, reopening, invalid/refunded keys, failed network, deactivation, reinstall, and device move. Resolve the offline and key-storage policy before accepting payments. A checkout success redirect must never grant access.

No paid checkout or feature unlock is live until the gates pass. The candidate vssaas client protocol is documented separately; it is not a provider decision.
