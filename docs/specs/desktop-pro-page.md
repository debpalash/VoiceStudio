# Desktop Pro checkout release contract

VoiceStudio Free retains unlimited local voice creation, transcription, dubbing, Stories, Audiobooks, batch jobs, local exports, reusable recipes and watch folders. Remote compute devices, remote workers and GPU sharing are VoiceStudio Pro features and are no longer included in the open-source app. The remaining proposed Pro scope is application licensing, additional batch rules/reports, revision history, delivery packages and project preflight; each requires review against existing free functionality before implementation. Application licensing does not grant model or generated-output rights.

VoiceStudio Pro is on sale and working (owner-confirmed 2026-11-06). The current page presents $99 per user yearly or $199 per user lifetime. Yearly renews; lifetime is one payment with no renewal and includes lifetime updates. Enterprise is a contact plan for customised deployment, policy controls, SSO/SAML, opt-in analytics and dedicated support. Pro does not change GNU AGPL-3.0 software distribution rights; a separate commercial agreement handles closed-source distribution. Payment/licensing provider, default Pro engine and private-repository versus plugin structure remain undecided.

The open-source Electron Pro page shows Pro, Lifetime, and Enterprise cards in one row. Pro and Lifetime let buyers select 1–99 users, show the calculated total, and link to `https://voicestudio.sh/pro` with the plan and quantity. Enterprise links to the commercial contact page. The open-source page does not check licence status or expose activation and deactivation controls. The open-source app contains no licence client and makes no licensing network calls; activation belongs to a separate Pro distribution. Lemon Squeezy is the candidate provider; choosing it for production remains a separate decision. If selected, the website may show its hosted checkout only when all release gates are true and both live offers are verified. Lemon Squeezy handles payment, receipts, and emailing licence keys. A Pro distribution may activate, validate, and deactivate a key through its public License API. It must accept only the configured store, product, and one of the two purchasable plan variant IDs, and main must never return the key to the renderer after submission. Free workflows do not require a network call.

## Release gates

These gates were written before launch and now apply to any new paid capability or checkout change. This document doesn't record the evidence for each gate at launch.

- Finalize additional paid capabilities, then implement their entitlement checks in Electron main/backend. Keep existing free recipes, watch folders and local generation outside Pro gates; remote compute devices, remote workers and GPU sharing belong to VoiceStudio Pro rather than this repository. Verify new paid capabilities on macOS, Windows and Linux. Until this is done, `VOICESTUDIO_PRO_FEATURES_RELEASED` stays unset.
- Fulfil purchased user quantity as the licence activation entitlement. Lemon Squeezy checkout quantity changes the charge but does not by itself change a variant's fixed activation limit, so a verified webhook or equivalent fulfilment step must set and audit the purchased activation count before multi-user checkout is enabled.
- Create live yearly and lifetime Lemon Squeezy variants with licence keys enabled. Verify the yearly subscription interval and the lifetime non-expiring key. Record store, product, and both variant IDs. Confirm each displayed price against checkout, tax presentation, activation limit, renewal and cancellation terms, and refund policy in a live checkout. Test variants must never be used for a production build.
- Review and approve desktop Pro purchase terms and privacy wording with qualified counsel. Until approved, `VOICESTUDIO_PRO_TERMS_APPROVED` stays unset.
- Build the Pro distribution with the live store, product, and both variant IDs. Each must match the website's live offer. The open-source build cannot activate keys.
- Test purchase, email delivery, activation, reopening, invalid/refunded keys, failed network, deactivation, reinstall, and device move. Resolve the offline and key-storage policy before accepting payments. A checkout success redirect must never grant access.

No new paid capability or checkout change goes live until these gates pass. The candidate vssaas client protocol is documented separately; it is not a provider decision.
